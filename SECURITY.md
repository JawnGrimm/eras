# Security Policy

## Supported versions

Security fixes are currently considered for the latest code on the `main` branch. There are no separate supported release branches or published version support windows at this time.

## Reporting a vulnerability

Please do not report security vulnerabilities in public issues, discussions, or pull requests.

Use GitHub's **Report a vulnerability** option in the repository's Security tab if private vulnerability reporting is enabled. If that option is unavailable, contact the repository owner privately through their GitHub profile and request a secure reporting channel. Do not include exploit details in a public message.

Please include, when possible:

- A description of the suspected vulnerability and its potential impact.
- Affected files, components, versions, or commit references.
- Reproduction steps or a proof of concept that does not expose real user data.
- Any suggested mitigation.

## What to expect

The project is maintained by a small team, so response times may vary. The maintainer will acknowledge reports when practical, investigate the issue, and coordinate a fix or mitigation. Please allow reasonable time for investigation before public disclosure.

Do not access, modify, or disclose data that does not belong to you while investigating a suspected vulnerability.
